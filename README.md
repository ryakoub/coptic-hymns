# Coptic Chanter: website and hymn content

The hymns for copticchanter.com and the Coptic Chanter app. A push to `main` publishes the website, and the app picks up the new catalog on its next check (at launch, at most every 6 hours), without an App Store update.

## Fixing a hymn's titles or places

Titles (English, Coptic, Arabic), tune names, where each hymn appears in the app and in what order, its kind (recital or melismatic) and your notes are kept in each hymn's `info.json`. Edit them all at once as a spreadsheet:

1. **Export** every hymn to a sheet:
   ```
   python3 tools/titles.py export ~/Downloads/hymns.csv
   ```
2. **Edit** it in Numbers (one row per recording), then File → Export To → CSV, keeping the same name.
   - **Titles:** edit them on the hymn's own row. A row whose `text` column names another hymn is another tune of it: its titles come from that hymn, so only its `tune` name is edited there (e.g. "St. Gregory Liturgy").
   - **places:** separated by `;`, e.g. `annual/liturgy; holy-week/hymns`. The names are collection/section as in `catalog/library.json` (`annual`, `kiahk`, `great-lent`, `praises/midnight`, `holy-week/hymns`, …). `annual/liturgy@30` puts it at position 30 in that place only.
   - **order:** the position in its places, lower first; use steps of 10 so hymns can go in between.
   - **kind:** `recital` (quick, about a syllable to a note: good for the words lighting up as they're sung), `both` (it depends on the recording; then give each tune's row its own kind) or `melismatic` (long notes on few words: better learned with a score or hand-made marks, under the season's "Hymns with notation"). **pace** next to it (not editable) is how many Coptic words a minute the recording sings: under 10 is melismatic, 25 and over recital.
   - **group:** a sub-folder within its places, e.g. `Hoos | الهوسات` (English | Arabic). Hymns with the same group are shown together, in the order of the first of them; write the name the same way on each. It applies to the places in the hymn's own `places`, not to programs like the Mahragan that list it. A section can name its sub-folders in `catalog/library.json` (`"groups": [{"id": "canticles", "titles": {"english": "Canticles", "arabic": "الهوسات"}}, …]`): they then come in that order with those names, as the Midnight Praises' do (Intro, Canticles, Saints, Psalis, Theotokia, Conclusion); the id is the English name in lowercase with dashes. The app shows the sub-folders from its next update; until then they don't change anything.
   - **intro**, **intro_arabic:** a short introduction shown above the hymn's words in the app, under "About this hymn": what it is, when and how it is sung. Write it on the hymn's own row, like its titles. The app shows it from its next update.
   - **notes:** your notes on the hymn or its words. They are kept in the hymn's `info.json` (this repo is public) and aren't shown in the app yet.
   - An empty cell is left as it is; to clear one, write a single `-`.
3. **Import** it (it lists each change, and refuses places that are not in the library):
   ```
   python3 tools/titles.py import ~/Downloads/hymns.csv
   ```
4. **Rebuild the catalog** (it reports any mistakes), then commit and push:
   ```
   python3 tools/build_catalog.py
   ```

Or send the sheet, or the changes in words, to Claude.

Don't edit `docs/app/hymn-inventory.md`: it is generated by `tools/inventory/` and would be overwritten. It shows each hymn's own titles and places, so fixing them with the sheet fixes it too.

## Adding a music score to a hymn

A score (PDF) can follow the recording a hymn already has, so no second audio file is needed. It appears under the season's "Hymns with notation".

1. Put the PDF in iCloud Drive → Hymns → music_sheets and say which hymn it is for, and who transcribed it (it becomes public, so it must be shareable).
2. Claude adds it as a draft in `content/notations/<id>/` (`notation.json` with `"recording": "<the hymn's recording id>"` and `"draft": true`, which keeps it out of the app) and gives the link to that recording's audio file.
3. Save that audio file on the iPad, open Mark Sync (copticchanter.com/mark-sync.html) with the PDF and the audio, and tap along: on the syllable you hear, where it is on the score; at least one mark per line, and a few more in long melismas.
4. Press **Export taps** (not the backup) and save the `.taps.json` in the same iCloud folder.
5. Claude puts the marks in `notation.json`, removes `"draft"`, tests it, and pushes.

## Order of the Midnight Praises

The Sunday Midnight Praises follow the Coptic Reader: a hymn's `order` is its number there × 10 (Tennav, number 3, is 30). A Mahragan version sits just after the hymn it goes with (Ten Thinou 25, after Ten Theeno 20), and the Theotokia parts still to add have their numbers kept free: (2)–(6) 180–220, (9) 260, (11)–(15) 280–320, (17) 340, (18) 350.

# Tools

Some helpers tools to import lyrics and attempt syncing with audio.

## Import Lyrics From Tasbeha.org

Use `tools/import_tasbeha_lyrics.py` to pull English and Coptic lyrics from a Tasbeha.org hymn page and write them into a hymn folder's `lyrics.json`.

Import lyrics only:

```bash
python3 tools/import_tasbeha_lyrics.py "https://tasbeha.org/hymn_library/view/23" "content/mahragan-keraza-2026/grades-5-6/level-1/doxology-st-mary-matins"
```

Keep leading `+` markers from Tasbeha:

```bash
python3 tools/import_tasbeha_lyrics.py "URL" "TARGET_FOLDER" --keep-plus
```

## Auto-Generate Timings

You can optionally attach timings while importing by passing the hymn audio file.

### Recommended workflow:

1. Run a first import + auto sync pass.
2. Listen and collect accurate verse start timestamps.
3. Save them in `TARGET_FOLDER/timing-anchors.json`.
4. Re-run with `--anchors` to lock verse starts.
5. Optionally switch to word sync (and melisma options) after verse starts are locked.

Available timing modes:

- `verse`: sets a `start` time for each lyric line
- `word`: adds a `words` array split by coptic word
- `auto`: chooses verse or word based on hymn style and text density

Import lyrics and detect verse timings:

```bash
python3 tools/import_tasbeha_lyrics.py "URL" "TARGET_FOLDER" --sync-audio "TARGET_FOLDER/audio.mp3" --sync-style verse
```

Import lyrics and detect word timings:

```bash
python3 tools/import_tasbeha_lyrics.py "URL" "TARGET_FOLDER" --sync-audio "TARGET_FOLDER/audio.mp3" --sync-style word
```

Import lyrics and sync with auto style hints:

```bash
python3 tools/import_tasbeha_lyrics.py "URL" "TARGET_FOLDER" --sync-audio "TARGET_FOLDER/audio.mp3" --sync-style auto --hymn-style melismatic
```

Use known verse starts (anchors) for stronger accuracy:

```bash
python3 tools/import_tasbeha_lyrics.py "URL" "TARGET_FOLDER" --sync-audio "TARGET_FOLDER/audio.mp3" --sync-style verse --anchors "TARGET_FOLDER/timing-anchors.json"
```

One-command wrapper (import and sync):

```bash
python3 tools/import_and_sync_tasbeha.py "URL" "TARGET_FOLDER" "TARGET_FOLDER/audio.mp3" --split auto --hymn-style melismatic
```

Melisma-aware word timing (opt-in, does not change default behavior):

```bash
python3 tools/import_and_sync_tasbeha.py "URL" "TARGET_FOLDER" "TARGET_FOLDER/audio.mp3" --split word --hymn-style melismatic --anchors "TARGET_FOLDER/timing-anchors.json" --melisma-auto
```

Use manual melisma hints to boost specific words:

```bash
python3 tools/import_and_sync_tasbeha.py "URL" "TARGET_FOLDER" "TARGET_FOLDER/audio.mp3" --split word --hymn-style melismatic --anchors "TARGET_FOLDER/timing-anchors.json" --melisma-auto --melisma-hints "TARGET_FOLDER/melisma-hints.json"
```

You can start from `melisma-hints.template.json`, save it as `melisma-hints.json`, then tune word boosts by line.

The new sync path uses `ffmpeg` + `ffprobe` and does not depend on `detect_pauses.py`.

Manual word-start application (reliable workflow):

Create a plain text file in this format:

```text
line 1: 4.28, 6.74, 17.68
line 2: 42.66, 44.69, 46.24
```

Then apply it to `lyrics.json` (and optionally update anchors):

```bash
python3 tools/apply_manual_word_starts.py "TARGET_FOLDER/lyrics.json" "TARGET_FOLDER/manual-word-starts.txt" --anchors "TARGET_FOLDER/timing-anchors.json" --audio "TARGET_FOLDER/audio.mp3"
```

This sets each word `start` to your provided values, sets each word `end` to the next word start, and aligns final word ends to the next verse boundary (or audio end for the last line).

### Player Sync Debug (Phone Testing)

When testing sync issues on phone, use this checklist.

1. Start local server in project root:

```bash
python3 -m http.server 8000
```

2. Find Mac LAN IP:

```bash
ipconfig getifaddr en0 || ipconfig getifaddr en1
```

3. Open on phone (same Wi-Fi):

```text
http://<LAN_IP>:8000/player.html?group=grades-3-4&level=level-1&hymn=pi-pnevma&syncDebug=1
```

Optional tuning flags:

- `syncDebug=1`: show seek telemetry overlay
- `seekDebounceMs=140`: ignore very fast repeated tap bursts
- `syncOffsetMs=0`: optional highlight delay override (default is `0`)
- Example:

```text
http://<LAN_IP>:8000/player.html?group=grades-3-4&level=level-1&hymn=pi-pnevma&syncDebug=1&seekDebounceMs=180&syncOffsetMs=250
```

If `target` and `current` look equal but heard audio is still behind on a specific device/browser, test `syncOffsetMs` in small steps (e.g. `80`, `120`).

## Seek-Friendly Audio Files

The website player and the app play the first of these that a hymn folder has: `audio.seek.m4a`, `audio.m4a`, `audio.mp3`. New hymns keep only `audio.m4a` (YouTube's own AAC stream, saved as it is); an MP3 copy is not needed.

Don't convert audio with ffmpeg's built-in AAC encoder: it adds audible blips to chant. When a conversion can't be avoided, use Apple's encoder:

```bash
ffmpeg -y -i "TARGET_FOLDER/audio.mp3" -c:a aac_at -b:a 192k "TARGET_FOLDER/audio.m4a"
```

Recommended stress test pattern:

1. Tap first word (or first verse)
2. Tap last word (or last verse)
3. Repeat 10-20 times quickly
4. Record overlay values for `target`, `landed`, `drift`, and `delta`

If testing does not reflect latest code, close and reopen the phone tab after each `player.js` version bump in `player.html`.
